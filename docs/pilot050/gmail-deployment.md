# Gmail transactional delivery — pilot

Gmail replaces Brevo for verification and password recovery. Only `gmail.send` is requested. The local OAuth authorization file is private and must never be committed or included in the APK. The owner must replace the previously exposed OAuth client secret, revoke the old grant as appropriate, and authorize the new credentials before production transfer. The sending account must be the intended TUNIBIZ account.

On PythonAnywhere, upload the freshly authorized JSON to a private location outside the repository, e.g. `~/.tunibiz/gmail-authorized-user.json`. Set permissions with `chmod 600 ~/.tunibiz/gmail-authorized-user.json`. In the existing private WSGI environment configuration, set `TUNIBIZ_GMAIL_CREDENTIALS` to the absolute path of that file and `TUNIBIZ_EMAIL_FROM` to the intended authorized email address. These are server-only variables. Do not expose the JSON via HTTP or GitHub. Keep `TUNIBIZ_REQUIRE_EMAIL_VERIFICATION=1`. No Brevo key is needed. Verify the Google OAuth grant and API access in the hosting environment, then test a real verification and recovery using an isolated test account. `ready()` checks local configuration, not deliverability. Google approval, sending quotas and possible token revocation remain operational considerations. Do not request broader Gmail scopes. Do not deploy or reload until release approval.
